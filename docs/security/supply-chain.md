# Supply Chain Security

This page describes what VoidLLM publishes for each release, which artifacts are signed, and how you can verify them.

## What is published per release

Releases are built by the `release.yml` GitHub Actions workflow when a `v*` tag is pushed.

| Artifact | Location | Signed |
|---|---|---|
| Container image (linux/amd64, linux/arm64) | `ghcr.io/voidmind-io/voidllm` | Yes, cosign keyless signature on the image digest |
| SLSA provenance (SLSA generator) | `ghcr.io/voidmind-io/voidllm` | Attestation generated by the `slsa-framework/slsa-github-generator` container workflow, signed keyless |
| BuildKit provenance | Image index of `ghcr.io/voidmind-io/voidllm` | Stored as an attestation manifest in the index, covered by the signed index digest |
| BuildKit SBOM (from 0.0.32) | Image index of `ghcr.io/voidmind-io/voidllm` | Stored as an attestation manifest in the index, covered by the signed index digest |
| Binaries (linux, windows, darwin; amd64 and arm64) | GitHub release assets | No signature is published for the binaries |
| Helm chart | GitHub release `voidllm-X.Y.Z` (stable releases only) | No signature is published for the chart |

The binary archives and the Helm chart are not signed. If you need a verifiable artifact, use the container image.

## Verify the image signature

The image is signed with [cosign](https://github.com/sigstore/cosign) in keyless mode. The signing identity is the release workflow of this repository, running on a version tag.

Use cosign 3.x. Signatures created by the current release workflow are not found by cosign 2.x.

```bash
cosign verify \
  --certificate-identity-regexp '^https://github.com/voidmind-io/voidllm/\.github/workflows/release\.yml@refs/tags/v[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z.]+)?$' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  ghcr.io/voidmind-io/voidllm:0.0.31
```

If you do not have cosign installed, run it from a container:

```bash
docker run --rm gcr.io/projectsigstore/cosign:v3.0.2 verify \
  --certificate-identity-regexp '^https://github.com/voidmind-io/voidllm/\.github/workflows/release\.yml@refs/tags/v[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z.]+)?$' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  ghcr.io/voidmind-io/voidllm:0.0.31
```

This command was run against `0.0.31` and against `0.0.32-beta.1` and reported that the cosign claims were validated, the entry was found in the transparency log, and the certificate chained to the trusted authority. Replace the tag with the version you run. For production, pin and verify by digest instead of by tag.

## SBOM and provenance

Releases carry BuildKit attestations in the image index, shown by registries as `unknown/unknown` entries. This is expected. They are covered by the signed index digest.

- **BuildKit provenance** is present on earlier releases too. For `0.0.31`, `docker buildx imagetools inspect ... --format '{{ json .Provenance }}'` returns SLSA provenance with the build arguments, the source repository and the commit.
- **SBOM** is new from 0.0.32. For `0.0.31` the SBOM query returns an empty result.

Inspect them with Docker Buildx:

```bash
# Provenance (works today)
docker buildx imagetools inspect ghcr.io/voidmind-io/voidllm:0.0.31 --format '{{ json .Provenance }}'

# SBOM (from 0.0.32 only)
docker buildx imagetools inspect ghcr.io/voidmind-io/voidllm:0.0.32 --format '{{ json .SBOM }}'
```

## Verify SLSA provenance

The `provenance` job in the release workflow also produces a signed SLSA provenance attestation using the SLSA generator. Verify it with [slsa-verifier](https://github.com/slsa-framework/slsa-verifier) (v2.7.1 was used here, downloaded from its GitHub release):

```bash
IMG=ghcr.io/voidmind-io/voidllm
DIGEST=$(docker buildx imagetools inspect $IMG:0.0.31 --format '{{.Manifest.Digest}}')
slsa-verifier verify-image $IMG@$DIGEST \
  --source-uri github.com/voidmind-io/voidllm \
  --source-tag v0.0.31
```

For `0.0.31` this printed `PASSED: SLSA verification passed`, with the builder `generator_container_slsa3.yml@refs/tags/v2.1.0` at the release commit.

## Vulnerability disclosure

See [SECURITY.md](https://github.com/voidmind-io/voidllm/blob/main/SECURITY.md) for scope and response timelines. Report vulnerabilities privately, either by email to security@voidmind.io or through [GitHub private vulnerability reporting](https://github.com/voidmind-io/voidllm/security/advisories/new). Please do not open a public issue.

## Dependency and code hygiene

These checks are configured in the repository:

- **Dependabot** opens weekly update pull requests for Go modules, npm packages (`/ui`), GitHub Actions, and the Docker base image.
- **CodeQL** analyzes Go and JavaScript/TypeScript on pushes and pull requests to `main`, and weekly.
- **OpenSSF Scorecard** runs on pushes to `main` and weekly, with results published (see the badge in the README).
- **Pinned actions**: GitHub Actions in the workflows are pinned to commit SHAs. The one exception is the reusable `slsa-github-generator` workflow, which is referenced by tag (`@v2.1.0`) because the SLSA verification model expects a tag reference.
